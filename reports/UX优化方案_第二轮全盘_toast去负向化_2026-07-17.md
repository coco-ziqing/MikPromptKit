## 二、问题定性

### 2.1 核心心理问题

当前错误文案的语言框架：
```
"上传失败: xxx"   → 动作指向用户，"你失败了"
"操作失败"         → 模糊否定，"你做错了什么"
"加载失败"         → 指责语气，"出错了"
alert('网络错误')  → 阻断式问责，"系统在吼你"
```

正确的语言框架（系统担责 + 建设性出口）：
```
"上传未完成，稍后再试"    → 系统没说"谁失败了"
"加载遇到问题，点击重试"   → 给出口
"网络不太稳定，请稍后重试"  → 系统承认环境问题
```

### 2.2 设计原则（操作层面）

| # | 现有毛病 | 改造规则 |
|---|---------|---------|
| 1 | "XXX失败" — 否定用户操作 | "XXX未完成" 或 "XXX遇到问题" — 系统没能完成 |
| 2 | "操作失败" — 模糊，无出口 | 说清楚"什么没做到 + 可以做什么" |
| 3 | alert() — 阻断式吼叫 | toast/inline 提示，非阻断 |
| 4 | "网络错误" — 甩锅给网络 | "网络不太稳定" + 自动重试/手动重试按钮 |
| 5 | "加载失败" — 终结态 | "加载未完成" + 点击重试链接 |
| 6 | "告警" — 监控感 | "提醒" — 友善关心 |

## 三、改造方案

### P1-A：消灭 alert() 阻断弹窗（~15 处）

**问题**：`alert('加载失败')` / `alert('网络错误')` — 阻断用户操作流，系统仿佛在训斥用户。

**方案**：全部替换为 toast 提示（系统 toast 已有 pk_terms.TOAST 底座可用），非阻断式。

涉及文件：
- `asset_library_ui.js` L148/L149/L169 — 改用 toast
- `device_manager_ui.js` L32/L175/L200 — 改用 toast
- `file_steward_ui.js` L228/L230 — 改用 toast
- `admin_users.js` L176/L239/L246 — 改用 toast（或保留 alert 因操作关键）

**注**：破坏性操作确认（如删除用户）的 `confirm()` 保留，但部分改为「建议先归档再注销」类提示。

---

### P1-B：Toast 文案全局去 X 失败化（~250+ 处）

**核心改写对照表**：

| 现有 | 改为 | 理由 |
|------|------|------|
| 操作失败 | 操作未完成，稍后再试 | 去"失败" |
| 创建失败 | 创建未完成 | 同上 |
| 保存失败 | 保存未完成，稍后再试 | 同上 |
| 删除失败 | 未能删除，请稍后再试 | 同上 |
| 加载失败 | 加载未完成，点击重试 | 给出口 |
| 上传失败 | 上传未完成 | 同上 |
| 导出失败 | 导出未完成 | 同上 |
| 导入失败 | 导入未完成 | 同上 |
| 网络错误 | 网络不太稳定，请稍后重试 | 系统承认环境问题 |
| 未知错误 | 遇到意外情况，请稍后再试 | 同上 |
| 匹配失败 | 匹配未命中 | 中性化 |
| 解析失败 | 未能解析，请检查格式 | 给出口 |
| 回滚失败 | 回滚未完成 | 同上 |
| 还原失败 | 还原未完成 | 同上 |
| 生成失败 | 生成未完成 | 同上 |
| 关联失败 | 暂未关联成功 | 同上 |
| 移除失败 | 暂未移除 | 同上 |
| 更新失败 | 更新未完成 | 同上 |
| 超时 | 响应超时，正在重试... | 主动行动 |
| 请求失败 | 请求未响应，请稍后重试 | 同上 |
| 翻译失败 | 翻译未完成 | 同上 |
| AI分析失败 | AI 暂未完成分析 | 同上 |

**实施方案**：因改动量巨大（250+ 处），不逐行修改每个 JS 文件。改为在 `pk_common.js` 或 `pk_terms.js` 中新增 **通用 toast 文案映射函数**：

```js
// pk_terms.js 新增
PK_TERMS.toastText = function(action, detail) {
  var map = {
    create: '创建未完成',
    save: '保存未完成，稍后再试',
    delete: '未能删除，请稍后再试',
    load: '加载未完成，点击重试',
    upload: '上传未完成',
    export: '导出未完成',
    import: '导入未完成',
    network: '网络不太稳定，请稍后重试',
    unknown: '遇到意外情况，请稍后再试',
    rollback: '回滚未完成',
    restore: '还原未完成',
    generate: '生成未完成',
    link: '暂未关联成功',
    update: '更新未完成',
    timeout: '响应超时，正在重试...'
  };
  var base = map[action] || (action + '未完成');
  return detail ? (base + '：' + detail) : base;
};
```

然后在各 JS 文件 `catch(e)` 块和 `.showToast()` 调用中替换掉硬编码的 "XXX失败"。这需要逐个文件修改——约40个文件的 catch 块。

**注**：i18n 键（如 `App._t('common.op_failed', '操作失败')`）的 fallback 值一并改，但 key 保留不动（key 只是标识符）。

## 五、不做清单

| 项 | 原因 |
|----|------|
| `error` / `danger` 作为 toast 类型参数 | 这是 UI 样式标识，不改变（变量名不动，只改文本） |
| `catch(e)` 结构本身 | 标准 JS 错误处理，结构不改造 |
| `setTimeout(s, 60000)` 等硬编码数值 | 与 UX 无关的工程细节 |
| 后端 Python 代码 | 前端扫描显示后端已全部干净（无支配/评判式文案） |
| i18n key 名称 | key 是程序标识符，不改，只改 fallback 值 |
