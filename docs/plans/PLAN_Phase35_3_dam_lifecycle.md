## 一、DAM 完整生命周期（重新定义）

```
             ┌─ 发现 ──┐          ┌─ 存档 ──┐          ┌─ 检索调用 ──┐
             │ (Index)  │          │(Archive) │          │ (Retrieve)  │
             │          │          │          │          │             │
    Agent扫描 → 通知用户  →  选中文件 → 拷贝+压缩  →  搜索/浏览  →  预览代理
    检测新文件     │          存入资料库   落盘到服务器    找到资产       │
    提取元数据    │             │         指定归档目录    │        ┌─────┴──────┐
    生成缩略图    │         ┌───┴───┐    生成代理版    按需还原   下载代理文件  一键替换
    重复检测      │         │       │    标记只读      解压放回    (轻量预览)    (覆盖工作文件)
               手动选择   自动规则   │    冻结版本      设备盘     │
              哪个文件   命中即归档  │                             │
              要存入      (可配)    │                        发送给协作者
                                    │
                              工作文件继续改
                              下次再归档=新版本
```

### 关键转变

| | 原方案 | 新方案 |
|---|--------|--------|
| 归档是什么 | 建一条数据库指针，指向原始位置 | **拷贝 + 压缩 + 落盘**，成为独立存档副本 |
| 原始文件 | 唯一副本，删了就没了 | **工作文件**，可以继续改、删除、移动，不影响已归档的存档副本 |
| 磁盘占用 | 不占服务器空间 | 压缩后占用，但通过格式策略控制在合理范围 |
| 数据安全 | 依赖原始文件不丢失 | **存档副本是保险**，原始丢了也能从资料库还原 |
| 版本 | 每次覆盖 | 每次归档 **= 新版本**（旧版保留，可回退） |
| 检索 | 只能搜文件名 | 搜文件名 + 元数据 + 按项目浏览 + 预览代理文件 |

## 二、归档的完整功能设计

### 2.1 核心动作链（存入资料库到底做了什么）

```
用户操作：选中 scene02.c4d → 点击「存入资料库」→ 选择项目和模块

后台自动执行（6步，用户无感）：

  步骤1 ─ 拷贝
    原始文件 D:\Projects\scene02.c4d (256MB)
    → 通过网络传输到服务器临时目录

  步骤2 ─ 压缩（按文件类型选最优策略）
    .c4d 文件 → LZMA 压缩 → scene02.c4d.lzma
    256MB → 约 90MB（C4D 工程文件压缩比通常 60-70%）

  步骤3 ─ 生成预览版/代理
    C4D 文件：提取内嵌预览图（C4D 文件自带 thumbnail）→ scene02_thumb.jpg
    视频文件：ffmpeg → 720p h265 → 原 2GB → 代理约 80MB
    PSD 文件：提取合并图层 → preview.png

  步骤4 ─ 提取元数据
    文件名、大小、修改时间、格式版本 → meta.json
    DCC 特有元数据（C4D版本号、渲染器、贴图引用列表）→ 如有解析能力则记录

  步骤5 ─ 落盘到归档目录
    data/archive/<project_id>/<module>/<catalog_id>/
      master/scene02.c4d.lzma       ← 压缩存档（只读，原始字节可完全还原）
      proxy/scene02_preview.jpg     ← 预览图
      proxy/scene02_proxy.mp4       ← 代理视频（若有）
      meta.json                       ← 元数据
    data/archive/<project_id>/<module>/<catalog_id>/
      versions/                        ← 下次归档同文件时生成 v2/

  步骤6 ─ 入库 + 通知
    asset_catalog 写入记录（标记 archive_path、compression、proxy_path、frozen=1）
    通知：「scene02.c4d 已存入特种兵学校·角色设定，压缩后 90MB」
```

### 2.2 各文件类型的压缩/代理策略

| 文件类型 | 压缩方式 | 预计压缩比 | 代理/预览生成方式 |
|---------|---------|-----------|-----------------|
| .c4d / .blend / .max | LZMA（zip 级别 9） | 50-70% | 提取内嵌缩略图 |
| .psd / .ai | LZMA | 40-60% | Pillow 合成图层 → JPEG |
| .ae / .prproj | LZMA | 50-65% | 提取项目缩略图 |
| .mp4 / .mov / .avi | **不压缩**视频本身（已编码），只生成代理 | — | ffmpeg → 720p h265 CRF 28 |
| 图片序列 (.exr/.tiff) | LZMA 逐帧压缩 | 40-70% | 首帧 → JPEG |
| .png / .jpg / .webp | WebP 无损（PNG）/ WebP q85（JPG） | 30-50% | 自身缩小（512px） |
| .wav / .aiff | FLAC | 40-60% | Opus 64kbps |
| .fbx / .obj / .gltf | LZMA | 60-80% | 渲染缩略图（若有 ComfyUI） |
| .pdf / .docx | LZMA | 20-40% | 首页 → PNG |
| 其他未知格式 | LZMA 通用 | 取决于内容 | 文件类型图标 |

### 2.3 归档目录结构

```
data/archive/
  <project_id>/                          # 按项目隔离
    <module_key>/                         # 按模块隔离
      <catalog_id>/                       # 每个资产独立目录
        master/                           # 压缩存档本体（只读）
          scene01.c4d.lzma
        proxy/                            # 预览/代理版本
          scene01_thumb.jpg               # 缩略图
          scene01_proxy.mp4               # 视频代理（如有）
        meta.json                         # 技术元数据
        versions/                         # 历史版本
          v1/                             # 第一次归档
            master/scene01.c4d.lzma
            proxy/scene01_thumb.jpg
            meta.json
          v2/                             # 第二次归档（重新存入）
            master/scene01.c4d.lzma
            proxy/scene01_thumb.jpg
            meta.json
      <catalog_id_2>/
        ...
```

`asset_catalog` 表补充字段：

```sql
-- 新增
archive_path         TEXT,   -- 相对路径 master/xxx.lzma
compression          TEXT,   -- none|lzma|flac|webp_lossless...
compressed_size      INT,    -- 压缩后字节数
original_size        INT,    -- 原始字节数
proxy_path           TEXT,   -- 代理文件路径
proxy_type           TEXT,   -- thumb|video_proxy|audio_proxy
frozen               INT DEFAULT 0,  -- 1=已归档只读，不可覆盖
metadata_json        TEXT,   -- 提取的技术元数据
source_device_id     INT,    -- 来源设备
source_path          TEXT,   -- 原始位置（追溯用）
```

## 五、全链路对比：优化前 vs 优化后

```
【优化前 — 原始方案】
  扫描 → 上报索引指针 → 手动归档(建数据库行) → 原始文件仍在设备盘自生自灭

  问题：
  ❌ 原始删了 → 索引僵尸行
  ❌ 服务器上没有文件实体 → 不能预览、不能恢复
  ❌ 版本 = 覆盖指针 → 历史丢失
  ❌ 跨设备协作者看不到实际文件

【优化后 — DAM 全链路】
  扫描 → 通知用户 → 选择文件 → 拷贝+压缩落盘 → 生成代理 → 入库
                                              │
                            ┌─────────────────┴──────────────┐
                            │                               │
                      工作文件继续改                   存档副本冻结保护
                      (Agent 持续关注)                可搜索/预览/还原
                      下次改动后重新存入               各版本完整保留
                      → 自动成为 v2                  → v1 v2 v3 可回退
```

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| 归档本质 | 建指针 | **拷贝 + 压缩 + 落盘** |
| 数据安全 | 依赖原始文件不丢 | **存档副本是真正的保险** |
| 磁盘占用 | 0（只存元数据） | 压缩后可控（C4D 工程约省 60%） |
| 版本管理 | 覆盖 | **每次归档 = 新版本，全量保留** |
| 预览 | 依赖缩略图（35.1 已有） | + 代理文件（视频可播、图片可看） |
| 还原 | 无（没有实体可还原） | **一键解压放回指定位置** |
| 协作 | 看不到队友的文件实体 | **代理预览 + 按需还原到本机** |
| 检索 | 搜文件名 | **全文 + 元数据 + 标签 + 按项目/设备/时间** |
| 完整性 | 无校验 | **CRC 周期自检 + 损坏自动修复** |
| 自动化 | 全手动 | **自动归档规则 + 智能合集** |

## 六、技术实现注意事项

### 6.1 大文件传输

- 分块上传（8MB/块），断点续传
- 传输进度条（Agent GUI 显示）
- 传输失败自动重试 3 次

### 6.2 压缩效率

- 后台异步压缩，不阻塞 Agent 主循环
- >2GB 文件：流式压缩（不一次加载到内存）
- 压缩后校验 hash 确保可还原

### 6.3 磁盘水位

- 归档目录纳入现有磁盘自检体系
- 超过 80% → 通知提醒清理旧版本
- 可在策略中设置「归档目录最大占用」上限

## 七、一句话总结

> 归档不再是"记个名字"，而是"**拷贝一份压缩存档，冻结为不可变副本，生成轻量预览版**"。原始文件继续当**工作文件**随便改，存档副本是**项目的保险库**。要用了就搜/浏览/预览/还原，一条龙。
