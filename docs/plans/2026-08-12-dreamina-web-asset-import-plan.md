# 即梦网页端历史资产导入 — 开发方案（方案 B：浏览器自动化）

> 版本：v1.0（2026-08-12）· 状态：待评审 · 关联：v5.36.13 即梦历史资产导入（CLI 通道）
> 目标：打通「即梦官网/App 直接生成、未走 CLI」的历史作品 → 本地词卡模版式归档

---

## 1. 背景与目标

### 1.1 背景
v5.36.13 已实现从即梦 CLI 任务库拉取历史（1664 条，均为 CLI 提交的任务）。但**即梦官网/App 直接生成、未走 CLI 的历史作品不在其中**，CLI 无账号全量历史同步命令面。

### 1.2 目标
- 将即梦网页端「资产」页的全部历史作品（图片/视频 + 对应提示词 + 参数/时间）拉取到本地
- 与 CLI 通道**合流去重**，进入同一套词卡模版归档体系
- 体验上：连接向导化、进度可视化、可取消、可断点续传、可重试

### 1.3 边界（不做什么）
- 不做公网服务/多用户共享，纯局域网单机
- 不逆向 `a_bogus` 签名算法、不直连内部 API（脆弱且有风控）
- 不抓取他人作品/公开社区内容，仅本人账号资产
- 不做账号密码托管，登录态只存在于独立 Chrome 调试 profile（本机）

---

## 2. 调研结论（2026-08-12 实测）

| 项目 | 结论 |
|------|------|
| CLI 能力边界 | `list_task` 只含 CLI 提交任务；`query_result` 需 submit_id；无账号历史同步命令 |
| 社区逆向现状 | jimeng-api(1k★) / jimeng-free-api-all(475★) 均**只做生成**（sessionid 鉴权 + a_bogus 签名），无历史列表实现；已核实两仓库源码无 asset/history 相关代码 |
| 网页端结构 | 资产页 URL `/ai-tool/asset` 有效（SPA，JS 渲染）；导航含 灵感/生成/资产/画布；接口鉴权 = cookie `sessionid`；列表接口需要页面 JS 自带签名 |
| 本机环境 | Chrome 151（运行中，支持 CDP）；Python 3.14；playwright/selenium 未装（需新增依赖） |
| 关键推论 | 浏览器自动化**不需要逆向签名**：页面 JS 自己生成签名，我们通过 CDP Network 域读响应即可 → 提取器做成「观察真实请求 + 配置化解析」 |

## 3. 技术方案

### 3.1 总体架构

```
┌─ 前端（seedance_v2_video_ui.js 扩展）
│   📥 即梦资产 面板 ── 标签页：CLI 历史（现有） / 🌐 网页历史（新）
│       ├─ 连接向导 / 拉取控制 / 进度 / 结果管理
└─ 后端（新模块 backend/web_asset_capture.py + api 路由）
    ├─ Chrome 管理器：启动/探测/关闭调试实例
    ├─ 采集引擎（playwright sync API + CDP 会话）
    │     ├─ 导航 + 滚动加载（资产页）
    │     ├─ Network 监听 → 过滤列表/详情接口 → 解析 JSON
    │     └─ 媒体下载（原图/视频，断点续传）
    ├─ 提取器配置（capture_profile.json：接口关键词/字段映射，可调）
    └─ 入库归档：dreamina_assets 表（source='web'）+ 词卡
```

### 3.2 Chrome 管理（三模式，优先级从高到低）

| 模式 | 说明 | 适用 |
|------|------|------|
| **A. 独立调试 profile（默认/推荐）** | 以 `--remote-debugging-port=0 --user-data-dir=data/dreamina_web_profile` 启动独立实例；端口从 `DevToolsActivePort` 文件自动读取；首次运行引导扫码登录即梦，cookie 持久化在该 profile，之后免登录 | 不打扰日常 Chrome；可脚本启停 |
| B. attach 现有调试 Chrome | 探测 9222 端口已有调试实例（用户手动 `--remote-debugging-port=9222` 重启日常 Chrome） | 复用日常登录态 |
| C. 快速验证 | 无头模式（headless）仅用于抓取逻辑自测（无登录态，验证提取器） | 开发期 |

要点：
- 模式 A 端口用 `0`（自动分配），避免端口冲突；启动后轮询 `DevToolsActivePort`（≤10s）
- 已运行 Chrome 的 `--user-data-dir` 复用会失败 → 独立 profile 天然规避
- 采集完成后**保持实例运行**（下次增量同步秒连），面板提供「关闭调试实例」按钮

### 3.3 采集流程（单次同步）

```
1. 连接（connect_over_cdp）→ 建新标签页 → 打开 https://jimeng.jianying.com/ai-tool/asset
2. 登录探测：无登录态 → 返回「需要登录」→ 前端弹扫码引导（复用授权中心模式）
3. 启动 Network 监听（CDP Network.enable + responseReceived/getResponseBody）
4. 滚动加载：循环 Page 滚动到底 → 等待网络空闲（500ms）→ 直到列表长度不再增长（≤3 轮）或超时（5min）
5. 列表提取：过滤请求 URL 命中关键词(asset|list|history|my|work|record) 的 JSON 响应
   → 自动探测列表数组（递归找 array 字段）→ 字段映射（id/cover/prompt/url/time/model）
6. 详情补全：列表缺 prompt 的条目 → 逐个打开详情（或发现详情接口 URL 模式后批量调）
   → 从详情响应提取完整 prompt/参数/原图 URL
7. 媒体下载：原图直接下载；视频可选（默认仅下载 ≤50MB，超限提示）
8. 入库：web_asset_id（作品 ID）去重 → dreamina_assets（source='web'）→ 建词卡（content=prompt）
9. 产出统计：新增/跳过/失败/已下载/待下载
```

### 3.4 数据模型与去重

```sql
-- dreamina_assets 表扩展（幂等迁移）
ALTER TABLE dreamina_assets ADD COLUMN source TEXT DEFAULT 'cli';      -- cli | web
ALTER TABLE dreamina_assets ADD COLUMN web_asset_id TEXT DEFAULT '';   -- 网页作品 ID
ALTER TABLE dreamina_assets ADD COLUMN web_url TEXT DEFAULT '';        -- 作品页 URL
-- 幂等键：source='web' 时按 web_asset_id 唯一（部分索引）
```

- 去重策略：web 通道按 `web_asset_id`；与 cli 通道按 `submit_id` 互不干扰；同名作品（同提示词同时间）不做内容级去重（保真原则）
- 词卡归档：沿用「即梦历史资产」分组；`module='dreamina_asset'`，`meaning` 增加「🌐 网页来源」标记；`category='history_asset_web'`
- 文件目录：`data/dreamina_assets/web_images/`、`web_videos/`（与 cli 目录分离，避免文件名冲突）

### 3.5 断点续传与容错

| 场景 | 策略 |
|------|------|
| 进程中断/页面崩 | 已入库条目跳过；文件已存在且大小>0 跳过（`file_paths` 校验） |
| 单条提取失败 | 记 `extract_fail` 列表，面板可「重试失败」 |
| 下载失败 | 记失败原因（网络/404/风控），重试最多 2 次，退避 2s/5s |
| 登录态过期 | 检测到登录页特征 → 中止采集 → 提示重新扫码 |
| 风控（agent_detect） | 采集全程真实浏览器环境；滚动间隔 ≥400ms；每页操作后小随机延迟；失败即停并提示（不无限重试） |
| 页面改版 | 提取器配置化（3.6）；配置失效时降级 DOM 提取；并输出「需要更新采集配置」诊断信息 |

### 3.6 配置化提取器（capture_profile.json）

```json
{
  "asset_page_url": "https://jimeng.jianying.com/ai-tool/asset",
  "list_api_keywords": ["asset", "list", "history", "my_work", "record"],
  "detail_api_keywords": ["detail", "info"],
  "field_map": { "id": ["id", "asset_id", "work_id"], "prompt": ["prompt", "prompt_text", "text"], ... },
  "max_scroll_rounds": 60,
  "scroll_idle_ms": 500,
  "max_video_mb": 50
}
```
- 首次采集自动回写「实际命中的接口模式 + 字段映射」，二次同步直接复用（快）
- 提供「采集配置诊断」按钮：展示命中的接口 URL、字段、未识别字段 → 便于改版后快速适配

## 4. 操作流程（用户视角）

### 4.1 一次性配置（首次）
1. 打开「📺 任务面板 → 📥 即梦资产 → 🌐 网页历史」→ 点「连接 Chrome」
2. 向导：检测 Chrome → 一键启动独立调试实例（自动）
3. 首次扫码：实例内打开即梦登录页 → 手机扫码 → 自动检测登录成功 → 保存（cookie 持久化于独立 profile）
4. 完成：显示「已连接 · 已登录 · 可开始拉取」

### 4.2 日常使用
1. 打开「🌐 网页历史」→ 点「🔄 开始拉取」
2. 实时进度：已发现 N 条 · 已下载 M · 新增 K · 跳过(重复) J · 失败 F（进度条 + 分项计数）
3. 完成后自动刷新「已导入资产」列表（来源标注 🌐）
4. 增量同步：再点一次即只拉新作品（断点/去重自动）

### 4.3 管理
- 已导入列表：图片预览（点击放大）/ 视频播放 / 复制提示词 / 删除（文件+词卡+记录）
- 筛选：来源（🌐 网页 / CLI）/ 类型 / 时间
- 批量：失败重试、批量删除

## 5. 用户体验设计

### 5.1 面板结构（「📥 即梦资产」统一入口）
```
📥 即梦资产
├─ 统计条：总任务 | 图片 | 视频 | 成功 | 已导入（来源分布 🌐/CLI）
├─ 标签页：CLI 历史（现有） | 🌐 网页历史（新）
└─ 🌐 网页历史 页签
    ├─ 连接状态卡：🟢 已连接·已登录 / 🟡 已连接·未登录 / 🔴 未连接（+ 引导按钮）
    ├─ 拉取控制：🔄 开始拉取 | ⏹ 停止 | 🔁 重试失败 | 🧰 采集诊断
    ├─ 进度区：进度条 + 分项计数（发现/下载/新增/跳过/失败）
    └─ 结果列表：与 CLI 资产同款卡片（来源徽章 🌐、缩略图、提示词、参数、时间、操作）
```

### 5.2 关键交互原则
- **状态可见**：连接/登录/拉取每一步都有明确状态与下一步引导，无「转圈等结果」
- **可中断**：拉取可随时停止，已下载内容保留，下次续拉不重复
- **渐进披露**：默认一键拉取；高级选项（最大视频大小、滚动上限）折叠在「⚙ 高级」
- **失败友好**：失败条目红色角标 + 原因分类（网络/登录/风控/格式），一键重试；风控明确提示「已暂停，建议稍后再试」，不自动狂试
- **信任与安全**：界面明示「仅本机 · 独立浏览器实例 · 不碰日常 Chrome · 数据不上云」

### 5.3 文案基调（延续项目术语体系）
- 拉取 = 「同步我的即梦作品」；导入 = 「归档为词卡」；重复 = 「已在本地」
- 风控 = 「即梦暂时繁忙，稍后再试」而非「被拦截」

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 即梦页面/接口改版 | 中 | 配置化提取器 + 诊断面板 + DOM 降级；社区活跃可参考 |
| 风控（agent_detect/验证码） | 中 | 真实浏览器、合理节流、失败即停提示；不在无头模式跑真实采集 |
| Chrome 升级兼容性 | 低 | playwright 跟随 Chrome DevTools 协议，一般兼容 |
| 大视频下载占用磁盘 | 中 | 默认限 50MB/条，超限仅存元数据+提示；设置可调 |
| 独立 profile 登录态过期 | 低 | 检测后引导重新扫码（<1 分钟） |
| 新增依赖（playwright） | 低 | 纯本地 pip 包，无浏览器下载（用系统 Chrome） |

## 8. 验证计划

1. **P0 最小验证**：启动独立实例 → 打开资产页 → 抓取列表 5 条 → 人工核对（作品数/提示词/URL 完整性）
2. **登录流程验证**：扫码登录 → 登录态持久化 → 重开实例免登录
3. **全量拉取**：真实账号全量 → 与 CLI 通道数据合流检查（去重/来源标记）
4. **容错演练**：中途停止/断网/页面崩 → 断点续传正确性
5. **回归**：面板既有功能（CLI 资产导入/模版库）不受影响

## 9. 待确认问题（评审后定）

1. **登录态来源**：默认独立调试 profile（推荐，首次扫码一次、不打扰日常 Chrome）？还是复用日常 Chrome 登录态（需关一次浏览器）？
2. **抓取范围**：资产页全部历史（默认）？是否要时间范围/类型筛选？
3. **视频下载策略**：默认 ≤50MB/条（超出仅存元数据）是否可接受？或需要全量下载（大文件）？
4. **词卡分组**：沿用「即梦历史资产」分组（来源徽章区分）？还是新建「即梦网页资产」独立分组？
5. **增量同步**：是否要「打开面板自动静默同步」？
