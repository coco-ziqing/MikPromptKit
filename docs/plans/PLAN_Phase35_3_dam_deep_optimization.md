> 基于 PLAN_Phase35_3_dam_lifecycle.md 的系统性强化
> 聚焦六维：本地↔服务器协同 · 检索 · 资源占用 · 复用 · 恢复 · 防丢
> 生成：2026-07-16 | 状态：待确认后进入开发

---

## 〇、问题诊断 —— 当前方案的六个缺口

| # | 维度 | 当前做了什么 | 还不够 |
|---|------|------------|--------|
| 1 | 本地↔服务器 | Agent 上报 → 服务器存副本 | 单向流动。存完后本地和服务器状态脱钩，不知道谁新谁旧 |
| 2 | 检索 | 搜文件名 + 按项目浏览 | 不知道文件里有什么、不知道哪些文件相似、找"那个蓝色的机甲"找不到 |
| 3 | 资源占用 | LZMA 压缩 + 代理生成 | 同一个贴图被 5 个 C4D 引用 → 存 5 份；版本每版全量存 → 膨胀 |
| 4 | 复用 | 还原 / 下载代理 / 复制引用 | 不能直接从 ComfyUI 加载、不能拖进种子舞场景、不能外面引用的资产跟着项目一起走 |
| 5 | 恢复 | 单文件还原 | 不能一键还原整个项目、不能按时间点快照还原、不能只还原"差了什么" |
| 6 | 防丢 | 内容寻址 + CRC 校验 | 单服务器 = 单点故障。硬盘坏了全没；没有离机备份通道 |

## 一、本地 ↔ 服务器：从单向推送 → 双向状态机

### 1.1 核心模型：每个资产文件的三方状态

```
         ┌── 工作文件（本地设备盘）──┐
         │   用户在改的那个真实文件    │
         │   可能被编辑/移动/删除      │
         └──────────┬───────────────┘
                    │ 状态对照
    ┌───────────────┼───────────────┐
    │               │               │
    ▼               ▼               ▼
  本地            服务器          服务器
  索引指针       存档副本         代理文件
  (轻量元数据)   (压缩只读)       (轻量预览)
```

**每个资产在服务器同时维护三种状态**：

| 状态对比 | 含义 | 图标 | 用户看到的 |
|---------|------|------|-----------|
| ✅ 已同步 | 本地文件 = 服务器存档版本 | 🟢 | 正常，无提示 |
| 🆕 超前 | 本地有改动，比服务器存档新 | 🟡 | 「文件已更新，建议重新存入」 |
| 📦 只有存档 | 本地已删/找不到，但服务器有副本 | 🔵 | 「工作文件已移除，存档副本完好」 |
| ⚠ 存档缺失 | 索引有记录但服务器没实体 | 🔴 | 数据损坏告警 |
| ❌ 孤立 | 索引还在但本地和服务器都没了 | ⬜ | 可以清理 |

### 1.2 差异化同步提示（Agent 端 + WebUI 端）

```
Agent 端（文件管家助手窗口）：
  ┌─────────────────────────────────────────────┐
  │ D:\Projects\scene01.c4d                     │
  │ 🟡 本地已修改（7月15日存档，本地7月16日编辑）   │
  │    服务器上有存档副本，但不是最新版              │
  │    [重新存入]  [查看存档版]  [忽略]             │
  │                                              │
  │ D:\Projects\old_shot.c4d                     │
  │ 🔵 存档副本完好，但工作文件已不在原位            │
  │    [从存档还原到此处]  [从列表移除]              │
  └─────────────────────────────────────────────┘

WebUI 端（文件管家面板）：
  自动标注哪些文件比存档新 → 提醒归档
  自动标注哪些存档比本地新（别人还原过的新版本）→ 提醒拉取
```

### 1.3 本地缓存索引（离线不丢能力）

Agent 在设备本地维护一份轻量 SQLite（`pk_agent_cache.db`）：
- 记录已上报过的文件指纹
- 服务器断连时继续扫描，恢复后批量同步
- 本地就知道"哪些是新的、哪些改了"，不依赖服务器响应

## 二、检索：从搜文件名 → 搜内容 + 搜视觉

### 2.1 自动 AI 标签（存入时自动分析）

```
文件存入资料库 → 后台异步执行：

  图片 (.png .jpg .psd) → CLIP 视觉分析 → 自动标签
    poster.psd → 「机甲, 蓝色调, 赛博朋克, 特写, 主角」

  视频 (.mp4 .mov) → 提取首帧 → CLIP 分析 + 识别场景类型
    action_scene.mp4 → 「动作场景, 夜间, 爆炸, 第三人称」

  3D 文件 (.c4d .blend) → 提取缩略图 → CLIP 分析 + 解析材质节点名
    mecha.c4d → 「3D模型, 机器人, 金属材质, 关节」

  音频 (.wav .mp3) → 语音转文字(whisper) 或 频谱分析
    bgm_01.wav → 「管弦乐, 史诗, 战斗场景」
```

标签存入 `asset_catalog.metadata` + 关联现有 `tags` 表。搜索时：**「蓝色机甲特写」→ 命中 poster.psd + mecha.c4d**。

### 2.2 感知哈希去重 + 相似度搜索

```
存入时计算：
  perceptual_hash → 图片相似度（pHash）
  相同 hash = 同一张图 → 提示"此图已在项目X中有存档，要关联还是单独存？"

检索时：
  搜"和这个差不多的"→ pHash 汉明距离 < 阈值 → 列出相似资产
  场景：甲方给了参考图，想知道项目里有没有类似的
```

### 2.3 智能合集（保存搜索条件）

```
「特种兵学校 · 角色 · 已备份 · 最近30天」→ 保存为智能合集
  合集不存数据，只存条件 → 每次打开实时计算
  类似 iTunes 智能播放列表

「未归档的工作文件」→ 系统自动生成该合集
  让用户知道"有哪些文件还散落在设备上没存进资料库"
```

### 2.4 检索入口统一（一个搜索框搜所有）

```

│  状态：[已存档] [工作中] [有备份]                      │
│  项目：[全部] [特种兵学校] [宣传片]                     │
│  排序：[相关度] [最近] [大小] [使用频率]               │
│                                                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐             │
│  │ 🖼️       │ │ 🎬       │ │ 🖼️       │             │
│  │ poster   │ │ scene01  │ │ ref_img  │             │
```

## 三、资源占用：从按文件存储 → 去重 + 增量 + 冷热分层

### 3.1 全局内容寻址去重（跨项目共享）

```
原理：sha256 相同 = 同一文件 = 只存一份

场景：
  项目A · 角色模块 存了 brick_wall.png (12MB)
  项目B · 场景模块 也存了同一张 brick_wall.png
  项目C · 素材    再存一次

  当前方案：3 份 × 12MB = 36MB
  优化后：1 份 + 2 条引用 = 12MB + 几KB  → 省 66%

存储结构：
  data/archive/blob_store/
    1a/                     ← sha256 前两位
      1a2b3c4d...fullhash   ← 压缩后的实际数据（唯一一份）
    2b/
      ...

  asset_catalog.blob_hash → 指向 blob_store 中的文件
  多个 catalog 行指向同一个 blob → 自动去重
```

### 3.2 版本增量存储（v1=全量，v2+=差异）

```
scene01.c4d v1 (256MB) → 全量压缩存储 (90MB)
scene01.c4d v2 (262MB) → 计算与 v1 的二进制差异 (bsdiff) → 只存差异块 (约 8-15MB)
scene01.c4d v3 (258MB) → 计算与 v2 的差异 → 只存差异 (约 5MB)

还原 v3：取 v1 全量 → 应用 v2 diff → 应用 v3 diff → 解压 → 完整文件

版本链深度达到 5 时自动触发「全量快照」重置链，
防止过长的差异链导致还原变慢。
```

### 3.3 冷热分层存储

| 层级 | 位置 | 装什么 | 访问速度 | 成本 |
|------|------|--------|---------|------|
| 🔥 热 | 服务器 SSD | 最近 30 天存入的资产 + 所有代理文件 + 所有索引/元数据 | 即时 | SSD 空间 |
| 🧊 温 | 服务器 HDD | 30–180 天未访问的存档 | 首次访问需唤醒 | HDD 空间 |
| ❄️ 冷 | 外置备份盘 | >180 天未访问，但标记为"保留" | 需手动恢复 | 外置盘 |

```
自动化策略：
  30 天未访问 → 归档本体自动移至温层（代理文件留在热层方便预览）
  180 天 → 提醒「以下 12 个资产超过半年未使用，是否移至冷存储或删除？」
  
  冷存储资产被搜索/浏览时 → 代理文件可预览 → 需要原件时「从冷存储还原」
```

### 3.4 代理文件生命周期

```
代理文件占用也要管：
  原始文件被删除 → 代理文件保留 90 天（以备查看历史）
                   → 90 天后自动清理
  代理文件可手动「重新生成」
  统计面板：归档占用 / 代理占用 / 总占用
```

## 四、高效复用：从手动下载 → 直连工作流

### 4.1 ComfyUI / Seedance 直接引用

```
用户在 ComfyUI 工作流中需要加载一张贴图：

  传统方式：
    ComfyUI → Load Image → 选本地文件
    需要知道文件在哪台设备上 → 手动复制过来

  优化后（API直连）：
    ComfyUI → Seedance Loader（自定义节点）
    → 输入资产查询关键字 → 搜索资料库 → 选中 → 自动加载
    背后：服务器返回代理文件URL，ComfyUI直接请求
    不需要用户知道路径、不需要手动拷贝

    Seedance 场景编辑器：
    场景卡 → 添加参考资产 → 搜「机甲」→ 拖入场景
    → 场景保存时关联资产ID → 下次打开自动带出
```

### 4.2 项目包（一键打包项目的所有关联资产）

```
「导出项目 特种兵学校」
  → 自动收集：
      ☑ 项目中所有已归档资产（原始压缩版 + 代理）
      ☑ 项目的提示词词卡
      ☑ 种子舞场景数据
      ☑ 角色/场景设定
      ☑ 元数据清单
  → 打包为 .ptproj 文件（自包含 ZIP）
  → 给甲方/协作者 → 他们导入到自己的 PromptKit 实例
  → 自动解压到归档目录 + 重建索引 + 关联项目
```

### 4.3 资产引用追踪（知道谁在用）

```
brick_wall.png 被以下引用：
  ├── 特种兵学校 · 场景模块 · scene01.c4d（贴图节点）
  ├── 特种兵学校 · 场景模块 · scene03.c4d（贴图节点）
  ├── 宣传片 · 素材 · poster.psd（链接图层）
  └── 种子舞场景 · 第三幕（场景参考图）

  删除时 → 警告：「此资产被 4 个地方引用，确定删除？」
  移动时 → 「是否同时更新引用路径？」
```

## 五、恢复：从单文件还原 → 项目级一键恢复

### 5.1 项目快照（保存某个时间点的完整资产状态）

```
操作：项目详情页 → [创建快照]
  → 记录此刻该项目下所有资产列表 + 版本指针
  → 快照不复制数据，只记录"当时用的是哪个版本"
  → 极小空间占用（几KB）

恢复：
  选快照 → [恢复到此状态]
  → 自动计算差异：哪些资产有了新版本需回退、哪些资产新增（可选删除或保留）
  → 预览差异 → 确认 → 一键恢复
```

### 5.2 时间线回溯（按时间轴浏览资产变化）

```
┌─ 特种兵学校 · 资产时间线 ──────────────────────────┐
│                                                    │
│  7月16日 ─┬─ scene01.c4d v3 存入（机甲模型最终版）   │
│           ├─ poster.psd v2 存入（甲方确认版）        │
│           └─ bgm_01.wav v1 存入                     │
│                                                    │
│  7月14日 ─┬─ scene01.c4d v2 存入（骨架绑定完成）     │
│           └─ poster.psd v1 存入                     │
│                                                    │
│  7月10日 ─── scene01.c4d v1 存入（初版粗模）         │
│                                                    │
│  [7月16日快照 恢复] [7月14日快照 恢复] [+ 创建快照]   │
└────────────────────────────────────────────────────┘
```

### 5.3 差异恢复（只恢复缺少的/不同的）

```
场景：渲染工作站硬盘坏了，但之前存入过资料库

  差异恢复：
    ① 选择项目「特种兵学校」
    ② 选择目标设备「渲染工作站」
    ③ 系统自动计算：
        ☑ hero_model.c4d — 工作站缺，服务器有 → 恢复（90MB）
        ☑ scene01.c4d — 两方都有且版本一致 → 跳过
        ☑ env_map.hdr — 工作站有，但不是服务器存档版本 → [覆盖/跳过/保留两者]
        ☐ old_shot.c4d — 只有工作站有（未存档）→ 不在恢复范围
    ④ 只传缺失的 90MB，不重传存量
```

### 5.4 灾难恢复模式（全量重建）

```
最坏情况：服务器硬盘坏了，但外置备份盘有数据

  恢复流程：
    ① 连接外置备份盘 → 自动识别为恢复源
    ② 重建 blob_store → 从备份盘拷贝所有压缩存档
    ③ 重建 asset_catalog → 从备份盘读取索引快照
    ④ 重建代理文件 → 后台重新生成（因代理可能未备份）
    ⑤ 恢复完成后 → 通知各 Agent 重新同步状态
```

## 六、防丢失：从单机校验 → 多层冗余 + 离机备份

### 6.1 三层防丢体系

```
第一层 — 每日自检（服务器本地）
  ✓ 遍历 blob_store → 读取每个文件 → 校验 sha256
  ✓ 对比 asset_catalog 记录 → 实体是否存在
  ✓ 代理文件是否存在（缺失可重生成，非致命）
  ✓ 数据库 WAL 检查点
  ✓ 报告：N个健康 / M个损坏 / K个缺失

第二层 — 每周深度自检 + 自动修复
  ✓ 随机抽样 20% 的存档解压缩 → 验证可还原性
  ✓ 损坏文件 → 尝试从以下来源修复：
      ├── Agent 端设备盘上原始文件 → 重新拷贝压缩
      ├── 上次备份 → 恢复
      └── 同一 blob 的多余引用（如果还有另一份引用在）
  ✓ 无法修复 → 管理员告警 + 前端红色标记

第三层 — 离机备份（外置硬盘）
  ✓ 通过 Windows 任务计划 → 每周日 02:00 执行
  ✓ 备份范围：
      ☑ blob_store（所有压缩存档实体）
      ☑ 数据库完整 .dump（含所有表结构+数据）
      ☑ asset_catalog 快照
      ☐ 代理文件（可重新生成，不备份以节省空间）
  ✓ 备份存储到：用户指定的外置路径（USB HDD）
  ✓ 备份完成后发通知：「外置备份完成，共 12.3GB，1014 个资产」
```

### 6.3 关键资产保险锁

```
对标记为「重要」的资产提供额外保护：
  ☑ 重要资产强制外置备份（每周）
  ☑ 重要资产服务器保留两份副本（不同磁盘，如果有多盘）
  ☑ 重要资产不允许删除（需二次确认 + 管理员密码）
  ☑ 重要资产变更时自动创建快照
```

## 七、全量优化对照表

| # | 维度 | 优化前（dam_lifecycle 版） | 优化后（本版新增） |
|---|------|--------------------------|-------------------|
| 1 | 本地↔服务器 | 单向推送，存完脱钩 | **双向状态机**：同步/超前/只有存档/存档缺失/孤立 五态追踪 |
| 2 | 本地缓存 | 无 | Agent 本地 SQLite 缓存索引，离线继续工作 |
| 3 | 检索 | 搜文件名 + 按项目 | **+AI自动标签**（CLIP视觉分析/whisper音频转文字）、**+感知哈希相似搜索**、**+智能合集**（保存搜索条件） |
| 4 | 检索入口 | 分散在多处 | **一个统一搜索框**：跨项目/跨设备/跨文件类型 |
| 5 | 去重 | 无 | **全局内容寻址去重**（同sha256=1份实体+多引用，跨项目共享） |
| 6 | 版本存储 | 每版全量压缩 | **增量差异存储**（v1全量，v2+=bsdiff差异，链深5时全量快照） |
| 7 | 存储分层 | 单层 | **冷热分层**：SSD热→HDD温→外置冷，按访问频率自动流转 |
| 8 | 代理生命周期 | 生成后永不清理 | 90天未用自动清理、可手动重生成、用量统计 |
| 9 | 复用·ComfyUI | 手动下载→加载 | **API直连**：ComfyUI自定义节点搜索资料库直接加载 |
| 10 | 复用·Seedance | 无关联 | 场景卡关联资产ID，拖拽引用 |
| 11 | 复用·项目包 | 无 | **.ptproj自包含项目包**：一键收集所有关联资产→导出→导入 |

## 十、一句话总结

> 资产管理不是"把文件拷到服务器"就完事了。真正的 DAM 要回答四个问题：**这个东西在哪？（检索）有没有多余的？（去重）能不能还原？（恢复）会不会丢？（防丢）**。本次优化从"单向存储"升级为"双向状态管理 + 全局去重 + 增量版本 + 冷热分层 + 三层防丢 + 工作流直连"，让资料库从"一个备份目录"变成"项目的数字资产中枢"。
