# MikPromptKit 批量生成队列 · 手动功能验证指南

> 适用范围：v5.34.4 ~ v5.34.9（批量队列启动恢复 / 断点提醒 / 阶段性成果 / 生成预判 / 框选 / 队列总览）
> 验证环境：Windows + 局域网服务 http://127.0.0.1:8080 · 浏览器建议 Chrome/Edge 最新版
> 用时：约 30~40 分钟（含等待队列执行）

---

## 0. 前置准备

| 项 | 要求 |
|----|------|
| 服务 | 已在运行（本机 8080），版本 ≥ v5.34.9 |
| 登录 | admin / admin |
| 引擎 | 即梦已授权（本指南以即梦为主验证，ComfyUI/LibTV 流程相同） |
| 词卡 | 至少 30 张词卡（内置词库即可），其中部分已生成过缩略图、部分未生成 |
| 缓存 | 浏览器强刷一次（Ctrl+Shift+R），确保加载新版 JS（版本号 b6d3e9f1） |

**查看当前版本**：浏览器控制台或服务启动日志确认 `v5.34.9`。
**确认新版 JS 已加载**：F12 → Network → 搜 `app_collections_batch.js`，URL 应带 `?v=b6d3e9f1`。

> ⚠️ 当前库中若有正在执行的真实队列（如 56 个排队任务），验证时请用**少量新选词卡**操作，避免与真实队列混淆；重启验证前先记录队列状态。

## 1. 功能验证

### A. 生成队列总览可视化（v5.34.9）

**入口**：词库页 → 勾选若干词卡 → 工具/批量 → 「AI 批量生成缩略图」→ 弹窗打开。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| A1 | 打开批量生成弹窗，查看进度区 | 「📊 生成队列总览」面板出现（有任务时），3s 自动刷新 |
| A2 | 提交 5 张卡生成（见 D 流程） | 总览统计行显示：🟢 运行 1 · 🟡 排队 N · ✅ 完成 M · 进行中 x/y 张 |
| A3 | 观察任务卡片 | 运行中任务绿色高亮：`🟢 #id 即梦 生成中 3/5 [进度条] 当前: xxx 预计剩余 x分`；排队任务黄色：`🟡 排队中 0/5` |
| A4 | 等待 1 个任务完成 | 卡片变 `✅ 完成 5/5 成功 5/失败 0`，统计行累计成功数增加 |
| A5 | 关闭弹窗 | 总览面板消失；任务在后台继续（再次打开弹窗，总览恢复显示最新状态） |
| A6 | 制造失败 | 选 1 张无提示词内容的卡提交 → 任务卡片出现 `❌ 异常 + 错误摘要` |

**验收**：能一眼看清「队列里有多少任务、各自什么状态、全局进度」。

### B. 阶段性成果实时填入（v5.34.6）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| B1 | 提交 ≥10 张卡生成（batch_size 选 10） | 任务开始后，**每完成一张**：明细列表（任务进度下方）立即追加一行（缩略图 + 提示词前 40 字） |
| B2 | 观察缩略图网格 | 「生成结果」网格**实时**增加新图（不等整批完成） |
| B3 | 观察预览列表（本次处理词卡） | 对应卡行：占位图 → 实际缩略图、`⏳ 队列中` → `✅ 已生成`，**不整列刷新** |
| B4 | 完成 1 张后返回主界面 | 该词卡主界面缩略图约 2.5s 内出现（节流刷新） |
| B5 | 任务进行中，点击某卡优化结果 textarea 开始编辑 | 列表不被重绘打断，输入内容不丢失 |

**验收**：任务跑着就能看到每张卡实时产出，不用等整批 done；编辑优化结果不被轮询打断。

### C. 拖拽框选 + 自动滚动 + 批量免生成（v5.34.8）

**入口**：全词库模式（弹窗内「处理范围」选「全部词库」）或分组模式，预览列表较长（>20 张）。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| C1 | 在列表空白处按住鼠标左键拖拽 | 出现蓝色选框，框内卡片行实时高亮（蓝边+浅蓝底），底部显示「已框选 N 张」 |
| C2 | 拖到列表**下边缘**停留 | 列表自动向下滚动，新滚入的卡持续被框选 |
| C3 | 拖到**上边缘** | 列表向上滚动；**之前框选的行滚出顶部后仍保持高亮**（内容坐标，不丢选中） |
| C4 | 松开鼠标 | 框选结束，操作栏保持「已框选 N 张」 |
| C5 | 点「⛔ 批量免生成」 | 选中的卡全部置灰（opacity 0.45），按钮变「✅ 生成」，toast「已标记 N 张为免生成」 |
| C6 | 框选另一批 → 点「✅ 恢复生成」 | 卡片恢复亮度，参与生成 |
| C7 | 点「✕ 清除选择」 | 高亮与计数清除 |
| C8 | 边界：点击卡上的「👁 查看」「⛔ 免生成」按钮、textarea、滚动条 | **不触发**框选 |
| C9 | 原地单击列表空白 | 清除当前框选 |
| C10 | 提交生成（有免生成标记时） | 提交数量 = 总数 − 免生成数（toast 有提示） |

**验收**：长列表可一口气框选到底（自动滚动），滚出顶部的选中不丢，可批量免生成/恢复。

### D. 生成预判 + 提交前提醒（v5.34.7）

**构造风险卡**（用临时卡，验证后删除）：
1. 词库 → 新建词卡，**内容留空** → 保存（得到「无内容」卡）
2. 再建一张，内容粘贴 >800 字符（可复制多段文本）→ 保存（「超长」卡）
3. 找一张已生成缩略图的卡，用「免生成」保留、或选入待处理

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| D1 | 勾选：正常卡 × 3 + 空内容卡 × 1 + 超长卡 × 1 → 批量生成弹窗 → 开始生成 | 提交前弹出预判提醒：`⚠️ 预判发现 2 张词卡可能存在生成问题：无提示词内容 1 张（生成必然失败）· 提示词超长 1 张` |
| D2 | 点「确定」 | 仅提交 3 张正常卡；toast「已排除 2 张问题卡，本次生成 3 张」；预览列表中 2 张问题卡自动标记「免生成」置灰 |
| D3 | 再点开始生成（问题卡仍被排除） | 不再弹预判（已免生成），直接提交 3 张 |
| D4 | 有手动指定图/其他引擎图时提交 | 提醒含「本次将覆盖重生成：手动指定图 N 张、其他引擎图 N 张」 |
| D5 | 预判弹窗点「取消」 | 不创建任务，进度文本「已取消提交」 |
| D6 | 删除临时风险卡 | 词库中删除空内容/超长卡 |

**验收**：问题卡在提交前被拦截提醒，可一键排除；不会因为空内容/超长卡导致整批失败。

### F. 断点恢复 + 询问提醒（v5.34.4 / v5.34.5）

> 会中断当前队列，验证前**记录当前队列状态**（打开弹窗截图总览）。恢复机制保证不丢卡、不重复生成，可放心验证。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| F1 | 提交 ≥20 张卡生成，等第 1 个任务跑到 50% | 进度可见 |
| F2 | 重启服务：任务管理器结束 python 进程 → 双击「一键启动」 | 服务重新启动，日志出现 `[Batch] 队列恢复: 自动续跑 N 个任务` |
| F3 | 打开批量生成弹窗 | 弹出确认：`检测到上次中断的批量生成任务：已自动恢复 N 个中断任务（断点续跑，共 X 张词卡）` |
| F4 | 点「确定」（知道了） | 不再重复提醒（同一报告只提醒一次，localStorage 记录） |
| F5 | 观察队列总览 | 恢复的任务从**断点**继续：已完成张数保留（进度条不从 0 开始），且**没有重复生成**（明细里已完成的卡只有一条记录） |
| F6 | 再次重启 → 打开弹窗 | 无任务中断时**不弹**提醒（正常） |
| F7 | 服务中断时有关机/断电场景 | 下次启动同样自动恢复，任务不丢 |

**验收**：任何原因中断（重启/崩溃/断电）→ 启动自检发现断点 → 自动续跑 → 提醒用户 → 不丢卡、不重复生成。

## 3. 常见问题排查

| 现象 | 排查 |
|------|------|
| 功能看起来没变 | 强刷（Ctrl+Shift+R）；确认 JS URL 带 `?v=b6d3e9f1` |
| 预判弹窗不出现 | 确认所选卡中有风险卡（空内容/超长/文件丢失）；预判服务异常时保守放行不弹 |
| 框选不生效 | 确认按的是左键、起点在卡片行或空白处（非按钮/输入框/滚动条） |
| 队列总览不显示 | 弹窗打开状态下等 ≤3s；确认有任务（无任务时隐藏） |
| 提醒弹了多次 | 正常只弹一次（按报告时间戳去重）；清 localStorage `bgenResumeAck` 可重测 |
| 重启后任务消失 | 查看启动日志 `[Batch] 队列恢复`；DB 表 comfyui_batch_tasks 中任务状态应为 queued/running 被接管 |
| 需要看任务原始数据 | 服务日志 + `data/prompts.db` 的 `comfyui_batch_tasks` 表（status/current_index/results） |
