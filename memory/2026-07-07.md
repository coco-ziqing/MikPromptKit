# 2026-07-07 Session — Phase17.4 新建词卡全链路修复

## 会话概述
修复新建词卡从创建→保存→删除→回收站→恢复/永久删除的完整生命周期故障，共 **15 项修复**，涉及前端 5 文件、后端 1 文件。

## 修复清单

### 一、新建词卡弹窗无保存按钮
- **根因**: `word_editor.js` `_ensureModal()` 中 Phase17.3 分组选择弹窗之后有 5 行重复 HTML（`<div style="flex:1;"><input id="wcEditCategory">...</div></div>`），提前关闭弹窗 body → Footer 被挤出 `.modal-content`
- **修复**: 删除重复 5 行，HTML 标签从 25开/21闭 修复为 24开/24闭
- **版本**: word_editor.js v11.2 → v11.3

### 二、新建词卡预选分组竞态
- **根因**: `openCreate()` 调用 `this.open()`（async）但没有 `await`，紧接着 `_prefillGroupId = null` 在 `_loadGroups()` 完成前就执行了
- **修复**: `openCreate` 改为 `async` + `await this.open()`，预选完成后才清理
- **版本**: word_editor.js v11.3 → v11.4

### 三、词卡管理页新建按钮未传分组
- **根因**: `index.html` L174 `onclick="App.wordEditor.openCreate()"` 无参
- **修复**: `openCreate` 内部自动回退 `App.state.currentGroupId`
- **版本**: word_editor.js v11.4

### 四、删除到回收站报"提示词不存在"（跨表断层）
- **根因**: 数据库有 3 张词条表（`word_card` 1074条 / `prompt_cards` 152条 / `prompts` 156条），但 `v2.py` 的 5 个回收站 API 全只查 `prompt_cards` + `prompts`
- **前端修复**:
  - `app_collections.js` `_doTrashDelete`: `DELETE /api/prompts/{pid}` → `POST /api/v2/trash/batch-trash`
  - `app_editor.js` `_doDeleteFromEditor`: 同上
- **后端修复** (`v2.py`):
  - `batch_trash`: 三表依次查找 → 对应表写 `is_deleted=1`
  - `list_trash`: UNION ALL 三表 + 修复 `prompt_cards.subcategory` 列不存在 → `'' as subcategory`
  - `restore_from_trash`: word_card → prompt_cards 双表回退
  - `batch_restore`: 同上双表
  - `permanent_delete_prompt`: 同上双表
  - `empty_trash`: 同上双表
- **版本**: app_collections.js v10.2 → v10.13, app_editor.js v11.14 → v11.15

### 五、回收站不显示 word_card 词卡
- **根因**: `list_trash` 中 `prompt_cards` 表 `SELECT pc.subcategory` → SQLite 报 `no such column: pc.subcategory`
- **修复**: `pc.subcategory` → `'' as subcategory`

### 六、视频词卡清除缩略图不同步清除视频
- **根因**: 3 个清除路径全只调 `/thumbnail` DELETE，不管 `/video` DELETE
- **前端修复**: `word_editor.js` `_clearThumb()` 并发调两个 DELETE；`app_media.js` `clearCardThumbnail()` 同上
- **后端修复**: `delete_card_video` 增加同步清除 thumbnail（磁盘文件 + DB）
- **版本**: word_editor.js v11.4, app_media.js 版本升级

### 七、回收站永久删除按钮无效（WAL 锁死 + FK 约束）
- **根因链（3层）**:
  1. `db.commit()` 在 WAL 并发读写下立即抛 `database is locked`
  2. `empty_trash` 单事务逐条处理 292 条 → 持锁过久
  3. `atom_word_bridge` / `scene_card_ref` / `word_card_versions` 三表 FOREIGN KEY 引用 word_card，删除前未级联清理
- **修复**:
  - `permanent_delete_prompt` + `empty_trash`: `db.commit()` → `safe_commit()`（15次重试）
  - `empty_trash`: 每 50 条一 `safe_commit()` 释放锁
  - 关联表扩充: 增加 `atom_word_bridge(card_id)` / `scene_card_ref(card_id)` / `word_card_versions(card_id)` 的级联删除

## 关键经验

1. **WAL 模式下必须用 `safe_commit()`**: 裸 `db.commit()` 在心跳/语义搜索并发读写时会立即报 `database is locked`
2. **大事务必须分批**: 292 条逐条处理 + 单 `commit` → 锁死整库，应每 50 条 `safe_commit()` 一次
3. **回收站 API 必须三表兼容**: 新增 word_card 表后，所有回收站端点都应 UNION/回退三表
4. **FOREIGN KEY 影响级联删除**: 删除 word_card 前必须清理 `atom_word_bridge` / `scene_card_ref` / `word_card_versions`
5. **async 函数必须 await**: `openCreate` 的竞态导致分组预选完全失效
